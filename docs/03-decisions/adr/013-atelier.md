# ADR-013. Atelier: поиск работы владельца

Статус: принято 28.10.2026 (решения владельца D1–D15).

## Контекст

У владельца есть локальный Work Finder: CV под вакансию из банка достижений, учёт откликов, модели через Codex CLI по подписке. Нужен сервис на платформе, который сам находит вакансии, собирает двухстраничное CV, пишет тексты, отправляет отклики и ведёт их по доске. Пока только для владельца; многопользовательский режим позже.

## Решение

- Продукт `atelier`: `atelier.outegro.dev` (веб), `cv.outegro.dev/<хэш>/<Имя_Роль_CV>.pdf` (публичные ссылки на CV).
- Сервисы: `atelier-backend` (API, оркестратор задач, лёгкие шаги; в проде один процесс `ROLE=api,worker`), `llm-gateway` (Codex CLI, Claude CLI, MiniMax за одним API), `atelier-tex` (XeLaTeX, шаблон «Minimal violet» на две страницы), `atelier-browser` (Chromium для форм ATS), `atelier-web`. Правила CV — пакет `@outegro/atelier-engine`, источники вакансий — `@outegro/atelier-sources`, контракты — `@outegro/contracts/atelier`.
- Каждый шаг конвейера — тип задачи со своей очередью `atelier.task.<type>`; оркестратор хранит состояние шагов в своей БД `atelier`, воркеры без БД.
- Модель вызывается только там, где код не справляется: общий разбор вакансии (один раз на вакансию), матчи, текст, проверка фактов, тексты писем, сомнительные анкеты. Подбор, отбор кейсов, навыки, подгонка на страницы, шаблонные сообщения — код.
- Доступ: право `atelier.use` (есть у роли `owner`). Профиль владельца импортируется из Work Finder в БД, в репозиторий личные данные не попадают.
- Модели — подписка Codex владельца (личное использование; для других пользователей решение отложено до SaaS). Файлы — в Postgres (`STORAGE_DRIVER=pg`), пока нет бакета R2.
- Тяжёлые поды (`llm-gateway`, `atelier-tex`, `atelier-browser`) — PriorityClass `outegro-agents`: при нехватке памяти вытесняются раньше сервисов платформы.
- Формы ATS заполняет обычный Chromium; капчи и вход по логину не обходятся: такой отклик получает флаг «нужен человек».
