## Пошаговое выполнение

### C1. Подготовить контракт и проверку

Записать input/output, ожидаемые ошибки, затронутый инвариант, файлы и способ проверки. Для поведения использовать meaningful failing case/fixture; для визуального решения — конкретный preview; для документации — source comparison. Проверить реальные package scripts через [command map](../../../05-quality/command-map.md).

### C2. Реализовать ограниченный результат

1. Прочитать установленные taste/image-to-code skills и визуальные референсы. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
2. Подготовить читаемые desktop/mobile hero варианты внутри silver signature, не новые несвязанные концепции. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
3. Отдельно описать форму подписи, свет, материал, фон, место текста и CTA. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
4. Выбрать рабочий вариант по читаемости/узнаваемости/стоимости рендера и сохранить annotated brief. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.

### C3. Проверить

Пройти все TC этой карточки. Важен конечный business state, а не только HTTP 200. Для изменённого shared contract запустить проверки его consumers. Не заменять реальные DB concurrency tests моками. Все обращения к внешним provider в обычном CI — fake; real-provider evidence отдельно. Прочитать diff на secrets/лишние изменения.

### C4. Передать результат

Сохранить [task report](../../../07-templates/task-report.md) в `docs/09-evidence/L-03/<run-id>/report.md`: изменённые файлы, commit, команды, TC status, ограничения и resume point. Обновить status карточки и task-index.json согласованно. Если осталось обязательное blocked/not-run, task не done.

## Тест-кейсы

### TC-L-03-01: Читаемость

- **Дано:** Макет на small laptop и mobile.
- **Действие:** Посмотреть первый экран в масштабе 100%.
- **Ожидается:** Имя, роль и основной CTA видны без скрывающей их сцены.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-L-03-02: Авторство

- **Дано:** Исходные референсы.
- **Действие:** Сопоставить форму/контент.
- **Ожидается:** Не скопированы персонажи, имя и достижения другого автора.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-L-03-03: Реализуемость

- **Дано:** Описание материала и motion.
- **Действие:** Проверить список эффектов.
- **Ожидается:** Есть fallback и перечень обязательных/опциональных эффектов.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

Откатить конкретный app/shared UI diff к совместимой версии. Проверить потребителей общего package. Не удалять evidence прежнего измерения; новый профиль измеряется заново.
