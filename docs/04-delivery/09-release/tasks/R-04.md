Status: planned
Scope: base-release

## Цель и контекст

Deploy выполняется только в новом окружении и после concrete readiness; документ сам не запускает production.

Задача будущей реализации. Наличие этой карточки не означает, что код/сервисы уже существуют. Выполнять одну карточку, при необходимости передавать её по checkpoints. Соседний незакрытый контракт нельзя заменить догадкой.

## Пошаговое выполнение

### C1. Подготовить контракт и проверку

Записать input/output, ожидаемые ошибки, затронутый инвариант, файлы и способ проверки. Для поведения использовать meaningful failing case/fixture; для визуального решения — конкретный preview; для документации — source comparison. Проверить реальные package scripts через [command map](../../../05-quality/command-map.md).

### C2. Реализовать ограниченный результат

1. Проверить разрешённый target, immutable refs и fresh backup/bootstrap state. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
2. Применить GitOps release с migration/readiness gates. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
3. Выполнить smoke public/private routes, login, workers, webhook ingress и operational alerts. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
4. При failed gate исполнить совместимый rollback/forward-fix runbook и сохранить фактический outcome. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.

### C3. Проверить

Пройти все TC этой карточки. Важен конечный business state, а не только HTTP 200. Для изменённого shared contract запустить проверки его consumers. Не заменять реальные DB concurrency tests моками. Все обращения к внешним provider в обычном CI — fake; real-provider evidence отдельно. Прочитать diff на secrets/лишние изменения.

### C4. Передать результат

Сохранить [task report](../../../07-templates/task-report.md) в `docs/09-evidence/R-04/<run-id>/report.md`: изменённые файлы, commit, команды, TC status, ограничения и resume point. Обновить status карточки и task-index.json согласованно. Если осталось обязательное blocked/not-run, task не done.

## Тест-кейсы

### TC-R-04-01: Deploy

- **Дано:** Candidate прошёл readiness.
- **Действие:** Выпустить на согласованный target.
- **Ожидается:** Ready pods/routes/TLS и правильные digests.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-R-04-02: Migration fail

- **Дано:** Rehearsal broken migration.
- **Действие:** Пройти release path.
- **Ожидается:** Новое приложение не открыто, данные не откатили разрушительно.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-R-04-03: Smoke

- **Дано:** Production routes доступны.
- **Действие:** Пройти список без неразрешённых реальных списаний.
- **Ожидается:** User/private/ops пути работают, sales flag соответствует решению.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

## Откат и остановка

После появления данных не выполнять destructive down migration ради отката приложения. Проверить N/N-1 совместимость; использовать forward-fix. Финансовые/audit записи сохраняются, коррекция отдельной командой.

Если источник API/поведение провайдера неизвестен — выполнить документационный lookup по AGENTS.md и зафиксировать результат. Если требуется отсутствующий input — завершить независимую часть, оставить конкретный blocked TC и handoff. Не закрывать задачу обещанием «проверим позже».
