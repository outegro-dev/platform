### C2. Реализовать ограниченный результат

1. Настроить PG base backup/WAL во внешний private bucket. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
2. Определить consistent K3s SQLite/token и key backups отдельно от PG. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
3. Задать retention/encryption/freshness и отдельные restore credentials. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.
4. Сохранить runbook и провести test download/decrypt/list без публикации secrets. **Контроль:** сохранить конкретный diff/артефакт этого шага; сверить с контрактом и связанными TC ниже перед переходом дальше.

Все обращения к внешним provider в обычном CI — fake; real-provider evidence отдельно. Прочитать diff на secrets/лишние изменения.

- **Дано:** Backup completed.
- **Действие:** Проверить objects вне VPS и read restore credential.
- **Ожидается:** Копия доступна для восстановления, не только локальный log success.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.

- **Дано:** Создать test transaction после base backup.
- **Действие:** Проверить archive progress.
- **Ожидается:** WAL до тестовой точки доступен.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

- **Дано:** Bucket недоступен.
