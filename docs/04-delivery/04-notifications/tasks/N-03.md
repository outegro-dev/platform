# N-03. Delivery claim/retry/DLQ

Status: planned
Scope: base-release

## Цель и контекст

Delivery claim исключает конкурирующие workers, но crash после внешнего send остаётся отдельным случаем.

Задача будущей реализации. Наличие этой карточки не означает, что код/сервисы уже существуют. Выполнять одну карточку, при необходимости передавать её по checkpoints. Соседний незакрытый контракт нельзя заменить догадкой.

## Тест-кейсы

### TC-N-03-01: Два worker

- **Дано:** Одна pending delivery.
- **Действие:** Claim одновременно.
- **Ожидается:** Только текущий lease owner отправляет.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-N-03-02: После send

- **Дано:** Provider принял, DB result не записан.
- **Действие:** Crash/restart.
- **Ожидается:** Unknown/idempotent recovery согласно adapter; exactly-once не выдуман.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-N-03-03: Permanent

- **Дано:** Неверный адрес.
- **Действие:** Обработать attempts.
- **Ожидается:** Остановка, без бесконечного retry.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.

### TC-N-03-04: Replay

- **Дано:** Dead-letter обычного сообщения.
- **Действие:** Повторить разрешённый command.
- **Ожидается:** Inbox не дублируется; auth-code replay запрещён.
- **Доказательство:** записать фактическое состояние/response/DB assertion или screenshot в test report. Для негативного сценария проверить также отсутствие запрещённого side effect.
- **Стартовый статус:** not-run.
