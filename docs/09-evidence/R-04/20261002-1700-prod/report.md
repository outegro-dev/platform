## TC-R-04-01 Deploy — pass

- CI (`0fb5144`, `23bb73c`) записывает в gitops каждое пересобранное приложение как `<тег коммита>@sha256:<digest>`; digest берётся из реестра после push (`docker buildx imagetools inspect`). Тег остаётся читаемым, а containerd тянет образ по digest: перезапись тега в GHCR не меняет запущенное.
- Проверено 02.10: все 9 приложений работают на `23bb73c653aa@sha256:…`; до этого digest всех 9 подов (`imageID`) совпал с digest из лога сборки CI (`a6a794e`).
- Маршруты и TLS: smoke 26/26 (ниже); сертификаты всех шести имён действительны ещё 57 дней.
- Упавший запуск CI ничего не выпускает, следующий охватывает и его изменения: база диффа — head последнего зелёного запуска (`a6a794e`; до исправления два приложения остались на старом образе).

## TC-R-04-02 Migration fail — pass

- Миграции — Job `*-migrate` (Argo CD PreSync, `BeforeHookCreation`, `backoffLimit: 2`, 300 с) для auth, notifications, payments, battleship. Упавший PreSync-хук останавливает синхронизацию до выкатки Deployment: продолжают работать прежние версии.
- Тест `runMigrations` в `packages/db` (`5eccc9f`), настоящий PostgreSQL: миграция из трёх операций (рабочий `ALTER`, `UPDATE`, деление на ноль) падает с SQLSTATE 22012; колонка не добавлена, данные не изменены, в журнале миграций одна запись; исправленная миграция применяется следующим выпуском. Ожидающие миграции применяются одной транзакцией.
- Риск: хуки всех сервисов в одном приложении Argo, поэтому упавшая миграция одного сервиса задерживает выкатку всех; watchdog сообщает через 15 минут.
