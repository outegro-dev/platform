# Notifications contract

NotificationIntent уникален по sourceEventId/template/recipient; Delivery по intent/channel. Inbox readAt независим от внешней доставки. Проектные состояния delivery: pending, leased, accepted, delivered при подтверждении провайдера, retry_wait, failed, expired, unknown. `accepted` нельзя переводить словом «прочитано».

Категории: auth, security, billing, service. Marketing выключен. Язык берётся из явного login locale либо профиля, fallback EN. Необязательный Telegram/email проверяет preferences и текущую channel binding непосредственно перед send. Unlink отменяет будущую отправку по удалённой связи.

Auth code не идёт в общую domain topic. N-02 выбирает короткий приватный delivery transport и фиксирует ACL/TTL/очистку. Если выбран encrypted payload, ключи раздельные и доступ только получателя; base64 не шифрование. Auth-code delivery после expiresAt запрещена. Retry не создаёт новый challenge; пользовательское resend создаёт разрешённый новый lifecycle по Identity policy.

Обычный retry: начальные кандидаты 15с/1м/5м/15м, максимум 4 повторные попытки после первой, ограничение актуальностью сообщения. Это инженерные defaults для проверки provider limits. Для auth retry ограничен TTL и urgency; нельзя механически использовать 15 минут. Permanent failures завершаются сразу. Provider timeout после send → unknown либо recovery по provider idempotency, не универсальная гарантия exactly-once.

Admin retry требует permission/reason/commandId и исключает login code. External send выполняется вне долгой transaction; claim и final state updates проверяют lease/version. Notification failure не откатывает оплаченную покупку.

Шаблоны (N-06) живут в коде notifications-backend. Ключ несёт версию (`billing.payment-confirmed.v2`): несовместимое изменение data — новый ключ, старый остаётся, пока его сообщения хранятся в inbox; ключи без суффикса считаются v1. Data проверяется схемой шаблона при приёме intent. `actionUrl` принимается только на origin `PUBLIC_WEB_URL`, `ACCOUNT_URL` или `PAY_WEB_URL` (та же схема, без учётных данных). Чужая ссылка отбрасывается при приёме и до пользователя не доходит, а само сообщение сохраняется и уходит со ссылкой шаблона на нашу страницу; сброс пишется в лог (ключ шаблона, producer, origin ссылки) и считается в `notifications_action_links_dropped_total{template}`. Так расхождение `PAY_WEB_URL` между payments и notifications не отправляет billing-сообщения в DLQ. Текст из data в письме экранируется, Telegram получает plain text. Суммы приходят в minor units с currency и scale и форматируются по языку получателя; время показывается в UTC с пометкой, часовой пояс получателя сервису неизвестен. Billing-сообщение говорит о доступе только то, что grant зафиксировал в той же транзакции: `access: pending` — «доступ ещё не открыт», без обещания; `access: withheld` (ключи `billing.payment-confirmed.v3`, `billing.subscription-started.v2`, `billing.subscription-renewed.v2`) — «платёж не открывает доступ, мы его вернём», без оплаченного периода. Прежние ключи (`.v2` покупки, `.v1` подписки) принимают только `active` и `pending` и остаются для сохранённых сообщений. Сообщение о возврате `billing.refund-recorded.v2` несёт `access`: `active` — доступ сохраняется (до `accessUntil` или бессрочно), `ended` — доступ по покупке закрыт, `withheld` — возвращённый платёж доступа не открывал (дубликат покупки, продление после отзыва): «этот платёж не открывал никакого доступа, деньги уже возвращаются», без слов о закрытом доступе. `billing.refund-recorded.v1` (только `accessUntil`, null читался как «доступ закрыт» и для дубликата) остаётся для сохранённых сообщений и intents, отправленных до перехода payments на v2; поэтому notifications-backend выкатывается раньше payments-backend. Producer-ы: payments (оплата, старт и продление подписки, отказ продления, отключение автопродления после подтверждения Lava, окончание подписки, учтённый возврат), identity (session-revoked, привязка и отвязка Google, добавление и удаление passkey — `security.passkey-added.v1`, `security.passkey-removed.v1`: в data только время, имя passkey в сообщение не попадает), сам notifications (подключение Telegram).
