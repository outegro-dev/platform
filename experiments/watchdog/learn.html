01 · что делает сервис

Короткий проход раз в пять минут

Сейчас в gitops работает shell-скрипт (sh + jq + kubectl). Обе новые реализации повторяют его поведение: те же проверки и те же сообщения в Telegram. Есть теневой режим DRY_RUN: сообщения печатаются в stdout, состояние не пишется.

  1. Собрать находки

    Все источники опрашиваются параллельно. Находка — это ключ и текст: pod:outegro/auth-backend · «not ready for 12 min».

  2. Сравнить с прошлым

    Состояние лежит в ConfigMap: для каждого ключа хранятся since, notified и message, плюс digestDay.

  3. Решить, что сказать

    Новая проблема, напоминание раз в 6 ч, восстановление, приветствие при первом запуске, сводка после 07:00 UTC.

  4. Отправить и запомнить

    Отправка в Telegram, затем запись состояния. Отмечаются только доставленные сообщения, поэтому недоставленное повторится на следующем проходе.

Что проверяется

  • Поды: CrashLoopBackOff или ImagePullBackOff, Ready не True дольше 10 мин, OOM за последние 15 мин
  • Узлы: NotReady, давление памяти, диска или PID
  • Диск сервера: занято 80 % или больше (statfs)
  • Сертификаты cert-manager: не готовы или истекают меньше чем через 14 дней
  • CloudNativePG: условия кластера и возраст последнего бэкапа (не старше 26 ч)
  • Argo CD: приложение не Synced или не Healthy
  • HTTP: 11 health-эндпоинтов должны ответить 200 за 10 с
  • Prometheus: алерты в состоянии firing, без шумовых и дублирующих

Почему есть «грация»

Некоторым проблемам дают время исправиться самим: деплой Argo CD идёт пару минут, а сайт может моргнуть на один запрос.

Зачем Plan и Apply разделены

Если Telegram не ответил, сообщение не считается отправленным, и следующий проход повторит его. Логика «что отправить» и «что считать отправленным» остаётся чистой, а сеть живёт между ними. Это проще тестировать, чем один метод, который и решает, и шлёт, и пишет.

Общий формат состояния

01

Порты: что ядру нужно от внешнего мира

Контракт, который подменяется в тестах. Языки по-разному отвечают на вопрос «кто кого знает».

go/internal/ports/ports.go
// Adapters in internal/adapters satisfy these interfaces implicitly
// (Go has no "implements"); tests satisfy them with small in-memory fakes.
package ports

// ErrNotFound reports that a requested object does not exist.
var ErrNotFound = errors.New("not found")

type ClusterSource interface {
	Pods(ctx context.Context) ([]domain.Pod, error)
	Nodes(ctx context.Context) ([]domain.Node, error)
	Certificates(ctx context.Context) ([]domain.Certificate, error)
	// PostgresCluster returns an error wrapping ErrNotFound when the
	// cluster does not exist.
	PostgresCluster(ctx context.Context, namespace, name string) (domain.PGCluster, error)
	Backups(ctx context.Context, namespace string) ([]domain.Backup, error)
	ArgoApps(ctx context.Context, namespace string) ([]domain.ArgoApp, error)
}

// Notifier delivers one message to the owner.
type Notifier interface {
	Send(ctx context.Context, text string) error
}

// Clock tells the time; tests use a fixed one.
type Clock interface {
	Now() time.Time
}
  • Реализация неявная. У типа просто есть такие методы, и слово implements не нужно. Поэтому интерфейс объявляют у потребителя (в ядре), а не рядом с адаптером.
  • ctx context.Context идёт первым аргументом по соглашению. В нём едут и отмена, и дедлайн.
  • Ошибка — второе возвращаемое значение. «Не найдено» передаётся sentinel-значением ErrNotFound, а проверяется через errors.Is.
rust/src/ports.rs
pub type BoxError = Box<dyn StdError + Send + Sync + 'static>;

/// Kubernetes, reduced to the domain structs the checks need.
#[async_trait]
pub trait ClusterSource: Send + Sync {
    /// All pods in all namespaces (the checks filter by namespace).
    async fn pods(&self) -> Result<Vec<Pod>, SourceError>;
    async fn nodes(&self) -> Result<Vec<Node>, SourceError>;
    async fn certificates(&self) -> Result<Vec<Certificate>, SourceError>;
    /// The CNPG cluster, `None` if it does not exist.
    async fn pg_cluster(
        &self,
        namespace: &str,
        name: &str,
    ) -> Result<Option<PgCluster>, SourceError>;
    async fn backups(&self, namespace: &str) -> Result<Vec<Backup>, SourceError>;
    async fn argo_applications(&self, namespace: &str) -> Result<Vec<ArgoApp>, SourceError>;
}

#[async_trait]
pub trait Notifier: Send + Sync {
    async fn send(&self, text: &str) -> Result<(), NotifyError>;
}

pub trait Clock: Send + Sync {
    fn now(&self) -> DateTime<Utc>;
}
  • Трейт реализуют явно: impl ClusterSource for KubeCluster. Компилятор сам проверит, что все методы на месте.
  • Send + Sync говорит, что объект можно делить между задачами tokio. Без этого не скомпилируется Arc<dyn ClusterSource> в многопоточном коде.
  • «Кластера нет» — это Ok(None), а не ошибка. Отсутствие выражено типом, и забыть обработать его нельзя.
  • Ошибка видна в сигнатуре и типизирована: SourceError, а не строка.
  • #[async_trait] нужен потому, что async fn в трейте пока нельзя вызывать через dyn. Макрос превращает метод в функцию, возвращающую Pin<Box<dyn Future>>.

/// `JoinSet::spawn` needs `'static + Send` futures, hence the cloned `Arc`
/// and the owned `Probe` in each task. Dropping the set aborts the tasks.
async fn probe_all(
    prober: &Arc<dyn Prober>,
    targets: &[Probe],
    deadline: Instant,
) -> Vec<ProbeResult> {
    let mut tasks = JoinSet::new();
    let mut task_index = HashMap::with_capacity(targets.len());
    for (index, probe) in targets.iter().cloned().enumerate() {
        let prober = Arc::clone(prober);
        let handle = tasks.spawn(async move {
            let status = bounded(deadline, prober.status(&probe.url)).await;
            (index, ProbeResult { probe, status })
        });
        task_index.insert(handle.id(), index);
    }
    let mut results = Vec::with_capacity(targets.len());
    while let Some(joined) = tasks.join_next().await {
        match joined {
            Ok(result) => results.push(result),
            // A panicked check must not vanish: it counts as "no response".
            Err(err) => {
                error!(error = %err, "HTTP check task failed");
                if let Some(&index) = task_index.get(&err.id()) {
                    let status = Err(SourceError::Request(Box::new(err)));
                    let probe = targets[index].clone();
                    results.push((index, ProbeResult { probe, status }));
                }
            }
        }
    }
    results.sort_unstable_by_key(|(index, _)| *index);
    results.into_iter().map(|(_, result)| result).collect()
}
  • Задача (spawn) может пережить функцию, которая её создала, поэтому компилятор требует 'static: всё нужное перемещается внутрь через move, а Arc клонируется.
  • Паника в задаче не роняет процесс. Она приходит как Err(JoinError) и превращается в «no response».
  • Результаты приходят в порядке завершения, поэтому в конце сортировка по индексу.

		if !slices.Contains(watched, p.Namespace) || p.Phase == phaseSucceeded || slices.Contains(p.OwnerKinds, ownerJob) {
			continue
		}
		key := "pod:" + p.Namespace + "/" + AppName(p)
		if reason, ok := badWaitingReason(p.Containers); ok {
			out = append(out, domain.Finding{
				Key:     key,
				Message: fmt.Sprintf("%s/%s: %s", p.Namespace, p.Name, reason),
			})
			continue
		}
		ready, found := domain.FindCondition(p.Conditions, domain.ConditionReady)
		status := domain.ConditionFalse
		since := p.CreatedAt
		if found {
			status = ready.Status
			if !ready.LastTransitionTime.IsZero() {
				since = ready.LastTransitionTime
			}
		}
		age := now.Unix() - since.Unix()
		if status != domain.ConditionTrue && age > int64(NotReadyAfter/time.Second) {
			out = append(out, domain.Finding{
				Key:     key,
				Message: fmt.Sprintf("%s/%s not ready for %d min", p.Namespace, p.Name, age/60),
			})
		}
	}
	return out
}

  • p := &pods[i] берёт указатель на элемент, чтобы не копировать большую структуру на каждой итерации.
  • Пакет slices (Go 1.21+) закрыл старую боль: Contains, Sort, Concat из стандартной библиотеки.

fn problem(pod: &Pod, now: DateTime<Utc>) -> Option<Finding> {
    let key = format!("pod:{}/{}", pod.namespace, app_name(pod));
    let bad_reason = pod
        .containers
        .iter()
        .filter_map(|c| c.waiting_reason.as_deref())
        .find(|reason| BAD_WAITING_REASONS.contains(reason));
    if let Some(reason) = bad_reason {
        return Some(Finding::new(key, format!("{}/{}: {reason}", pod.namespace, pod.name)));
    }

    let ready = find_condition(&pod.conditions, "Ready");
    if ready.is_some_and(Condition::is_true) {
        return None;
    }
    let since = ready.and_then(|c| c.last_transition).or(pod.created)?;
    let age = (now - since).num_seconds();
    (age > NOT_READY_AFTER_SECS).then(|| {
        Finding::new(key, format!("{}/{} not ready for {} min", pod.namespace, pod.name, age / 60))
    })
}

	switch {
	case strings.HasPrefix(key, "argo:"):
		return 900 * time.Second
	case strings.HasPrefix(key, "http:"):
		return 240 * time.Second
	case key == "prom:api":
		return 900 * time.Second
	default:
		return 0
	}
}

func Plan(prev *domain.State, findings []domain.Finding, facts domain.Facts, now time.Time) Outcome {
	nowUnix := now.Unix()
	old := domain.NewState()
	if prev != nil {
		old = prev.Clone()
	}
	current := domain.Dedupe(findings)
	slices.SortStableFunc(current, func(a, b domain.Finding) int { return cmp.Compare(a.Key, b.Key) })

	base := domain.State{Version: domain.StateVersion, DigestDay: old.DigestDay,
		Entries: make(map[string]domain.Entry, len(current))}
	var problems, reminders, recovered lines

	for _, f := range current {
		e, known := old.Entries[f.Key]
		if !known {
			e = domain.Entry{Since: nowUnix}
		}
		e.Message = f.Message
		if nowUnix-e.Since >= seconds(Grace(f.Key)) {
			switch {

			case nowUnix-e.Notified >= seconds(ReminderInterval):
				reminders.add(f.Key, f.Message)
			}
		}
		base.Entries[f.Key] = e
	}
	// … recovered, greeting, digest
}

pub fn plan(previous: Option<&State>, findings: &[Finding], facts: &Facts, now: DateTime<Utc>) -> Plan {
    let ts = now.timestamp();
    let empty = State::default();
    let prev = previous.unwrap_or(&empty);

    // First finding per key wins; iteration is in key order.
    let mut current: BTreeMap<&str, &Finding> = BTreeMap::new();
    for finding in findings {
        current.entry(finding.key.as_str()).or_insert(finding);
    }

    let mut next = State { findings: BTreeMap::new(), digest_day: prev.digest_day.clone() };
    let mut problems = Vec::new();
    let mut reminders = Vec::new();
    for (&key, finding) in &current {
        let (since, notified) = prev
            .findings
            .get(key)
            .map_or((ts, 0), |entry| (entry.since, entry.notified));
        if ts - since >= grace_secs(key) {
            if notified == 0 {
                problems.push(*finding);
            } else if ts - notified >= REMIND_AFTER_SECS {
                reminders.push(*finding);
            }
        }
        next.findings.insert(key.to_owned(), Entry { since, notified, message: finding.message.clone() });
    }
    // … recovered, greeting, digest
}
  • match с guard-ами (k if …) и обязательной веткой _: компилятор не даст забыть случай.
  • BTreeMap сортирован по ключу, поэтому дедупликация и стабильный порядок получаются одной структурой.
  • BTreeMap<&str, &Finding> хранит ссылки на входные данные без копирования. Компилятор гарантирует, что они живут дольше карты.

  key === 'prom:api' || key.startsWith('argo:') ? 900 : key.startsWith('http:') ? 240 : 0;

  const old = prev ?? emptyState();

  // первый по ключу побеждает, обход в порядке ключей
  const current = new Map<string, Finding>();

}

08 · упражнения

Чтобы язык осел в руках

Делай каждое упражнение сначала на Go, потом на Rust, и сравнивай, где компилятор помог, а где помешал. Тесты подскажут, если что-то сломалось.

  1. Новая проверка: перезапуски контейнеров

    Находка restarts:<ns>/<container>, если restartCount вырос больше чем на 5 за час. Нужно поле в домене, маппинг в адаптере kube и чистая функция с тестом. Заметь, сколько файлов затронуто в каждом языке.

  2. Грация из конфига

    Перенеси числа из Grace и grace_secs в переменную GRACE=argo:=15m,http:=4m. На Go — свой UnmarshalText, на Rust — FromStr и humantime. Добавь тест на неверный формат.

  3. Граница суток

    Напиши табличный тест (в Rust через rstest): сводка в 06:59:59 не уходит, в 07:00:00 уходит, повторно в тот же день не уходит, на следующие сутки в 07:00 UTC уходит снова.

  4. Сломай и посмотри

Термины, которые встретятся в коде

goroutine go
Лёгкий поток, которым управляет рантайм Go. Запускается через go f(). В Node аналога нет, ближе всего worker, но горутины в тысячи раз дешевле.
context.Context go
Отмена, дедлайн и значения запроса, которые передаются первым аргументом. Аналог AbortSignal, но встроен во всю экосистему.
errgroup go
Группа горутин с общей ошибкой и отменой контекста. Аналог Promise.all с отменой остальных.
неявный интерфейс go
Тип удовлетворяет интерфейсу, если у него есть нужные методы. Объявлять это не нужно.
race detector go
go test -race находит одновременный доступ к памяти без синхронизации во время выполнения тестов.
владение и заимствование rust
У значения один владелец. &T — чтение, &mut T — единственная запись. Проверяется при компиляции, сборщика мусора нет.
Result / Option и ? rust
Ошибка и отсутствие значения как обычные типы. ? возвращает ошибку наверх, это короткая форма if err != nil { return err }.
trait и dyn rust
Трейт — это интерфейс. dyn Trait даёт динамический вызов через таблицу методов, generics <T: Trait> — статический, без накладных расходов.
Arc rust
Atomic Reference Counted: общий указатель на данные, которые нужны нескольким задачам. Клонируется копированием указателя.
Send / Sync rust
Маркеры «можно передать в другой поток» и «можно читать из нескольких потоков». Их выводит компилятор, и они не дают собрать гонку.
Future, ленивость, drop rust
Async-функция возвращает future, который ничего не делает, пока его не опрашивают. Уничтожить future значит отменить работу.
newtype rust
Структура-обёртка над одним значением, например Secret(String). Даёт свой тип и своё поведение без накладных расходов.
провайдер и токен nest
Запись в providers: что подставлять (useClass, useFactory, useValue) по какому ключу (класс или Symbol).
application context nest
NestFactory.createApplicationContext — DI-контейнер без HTTP. Подходит для CronJob и воркеров.
ports & adapters
Гексагональная архитектура: ядро объявляет интерфейсы (порты), внешние реализации (адаптеры) подключаются в точке сборки.
distroless
Образ без шелла и пакетного менеджера, только рантайм-библиотеки. Меньше размер и меньше поверхность атаки.
CronJob и ConfigMap
Kubernetes запускает под по расписанию, под делает один проход и завершается. Состояние между проходами хранится в ConfigMap.
DRY_RUN, теневой режим
Новая версия работает рядом со старой: всё вычисляет, но не отправляет и не пишет. Результаты сравнивают перед переключением.
